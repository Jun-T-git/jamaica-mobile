# ADR-0004: ランキングを匿名認証 + `userScoresV2` に移行し、チャレンジのハイスコアを分離

- 記録日: 2026-09-19
- 状態: Accepted（[0003](./0003-firestore-ranking.md) の「既知の乖離」を解消）

## 背景

1. `firestore.rules` は `request.auth.uid == userId` を要求していたが、アプリは Firebase Auth を使わず AsyncStorage の自前 ID で書き込んでいた（0003 の既知の乖離）。ルールどおりなら送信は常に失敗し、ルールが緩ければ誰でも任意のスコアを書き込める状態だった。
2. スコア計算に欠陥があった。目標値ボーナスに上限がなく、生成器が稀に出す巨大な目標値（むずかしいで最大数万）を引くと 1 問で数十万点が入り、**ランキングが実力ではなく運で決まっていた**。

## 決定

- **Firebase 匿名認証**を導入し、その UID をランキングのドキュメント ID にする。ルールは本人のみ書き込み可・フィールドとスコア範囲を検証。
- スコア計算を見直し（目標値ボーナスに上限、スキップを正解数から除外）、出題も目標値を難易度別の範囲に制限した。
- 新旧のスコアは比較できないため、**ランキングは新コレクション `userScoresV2`** に、**端末内のチャレンジのハイスコアは `_v2` キー**に分離する。旧 `userScores` は読み取り専用で残す。

## 不変条件 #8（後方互換）との関係

これは永続化キーとランキング構造に対する**意図的な破壊的変更**である。

- 失われるもの: チャレンジモードの端末内ハイスコアの表示（旧キーのデータ自体は端末に残るが参照しない）と、旧ランキング上の順位。
- 残るもの: 練習（無限）モードのハイスコア、ニックネーム、サウンド等の設定。ドキュメント構造（`types/ranking.ts`）は変えていない。

運で決まった旧スコアを残すと、新しい計算式では更新できない「自己ベスト」になり、新記録時のみ行うランキング送信も永久に発生しなくなる。公平なランキングを成立させるために分離を選んだ。

## 影響

- 運用上の前提: Firebase コンソールで Anonymous 認証を有効化し、`firestore.rules` をデプロイすること。
- 送信失敗（オフライン・未設定）はゲーム進行を止めない。失敗分は端末に控えて次のゲーム終了時に再送する。
- 自分の順位は件数の集計クエリで取得する（コレクション全件を読まない）。
