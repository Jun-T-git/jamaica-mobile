# MONETIZATION — 提供範囲とリリース検証

## 提供範囲

- **買い切り「広告なし・解答例見放題」**: 全画面広告を削除し、そのプレイの全問題のヒント・解答例を動画視聴なしで常時閲覧できる。日本ストアの通常価格は **税込500円・買い切り**（2026-10-05 決定）。割引演出は設けない。アプリ内では StoreKit のローカライズ済み商品価格を表示する。メニュー・設定・リザルトから共通の購入画面へ直接進み、購入・復元できる。
- **任意のリワード広告**: 1 回の報酬獲得で、その時点から 1 時間、以降のプレイも含めて解けなかった問題を開き、練習・ヒント・解答例を利用できる。問題ごとの広告視聴は不要。終了時刻を端末に保存し、再起動しても残り時間を引き継ぐ。保存失敗時もそのセッションで獲得済みの権利は取り消さない。
- **対象問題と無料範囲**: 正解・スキップ・終了時の未解答をプレイ順に記録する。リザルトから全問題一覧と各問題の目標・数字を無料で閲覧し、正解した問題は元の 5 数字から無料で解き直せ、ヒント・答えも無料で使える。解けなかった問題（スキップ・未解答）は詳細を開く際に購入またはリワード権利を確認し、未解放なら動画視聴の確認を出す。ノード→演算子→ノードの操作、戻す・最初から・正誤表示を備える。本番のスコア・制限時間には影響しない。詳細の元結果は「前回 正解/スキップ/未解答」として練習の正誤表示と区別する。「解けなかった」フィルターでスキップと未解答に絞れる。集計もこの 2 種類を「解けなかった」としてまとめる。次のプレイ開始時に一覧を置き換えるため、過去のプレイの履歴保存ではない。正解演出中に終了した問題は正解として扱い、未解答として重複追加しない。
- **ヒント・答えの表示**: 問題を開くと練習盤面を表示する。開いた問題ではヒント 1/2/3 で解答例の最初の 1/2/3 計算、答えで全計算を段階表示できる。現在の練習に合わせた次の一手ではなく、元の数字からの解答例を示す。閲覧中も練習の手順は保持し、「自分の手順に戻る」（答え表示時は「練習に戻る」）か同じ段階の再タップで戻れる。ヒント 1〜3 では「ヒントの続きから解く」を選び、その途中状態で練習履歴を置き換えて続けることもできる。別の問題へ移動すると練習は初期状態になる。権利は問題を開く操作で確認する。期限が切れても開いている問題の練習・ヒント・答えは継続できるが、解けなかった問題を再度開く際は権利が必要となる。練習とヒントは共通座標を使い、元の葉の位置と盤面の高さを揃える。解答例は隣接項の組み合わせを優先し、解がなければ全組み合わせから探す。線が常に交差しない保証はない。上部に一覧への戻る/閉じる操作、下部にフィルター内の前後問題への切替を置く。
- **インタースティシャル**: リザルトからメニューへ戻る時のみ。再プレイには表示しない。ゲーム回数・起動後猶予・前回全画面広告からの間隔をすべて満たし、購入権利確認済みの場合だけ表示する。購入者とリワード閲覧期間中は表示しない。未ロードなら遷移を優先する。
- **バナー**: 全画面で廃止。無料ユーザーを含めてバナー広告は表示しない。判断と参照した実績は [ADR-0020](./decisions/0020-remove-banner-ads.md)。

閾値と広告 ID の正は `config/monetization.ts`、表示判定は `utils/monetizationPolicy.ts`。実装の境界は [ARCHITECTURE.md](./ARCHITECTURE.md)、採用理由は [ADR-0008](./decisions/0008-purchase-and-rewarded-review.md)、復習対象の拡張は [ADR-0012](./decisions/0012-review-all-played-problems.md)、初期盤面との切替は [ADR-0013](./decisions/0013-review-tree-initial-state.md)。

## リザルトでの導線

`screens/ChallengeResultScreen.tsx` は上側にスコアと「今回の記録」、下側に復習カードと「もう一度」「ホームに戻る」の操作群をまとめる。ランキングが集計期間中なら順位・人数の代わりにエントリー済み・集計中を案内する。「解答例を見る・復習する」カード全体をタップすると問題一覧を開き、再プレイを単一の主要ボタンとする。下部の 2 ボタンは左右等幅・アイコン付きとし、左の再プレイはアクセント青、右のホームは背景色と境界線で補助操作として示す。正解がある場合は平均回答時間を常時表示し、チャレンジでは正解数・最大コンボ・基準ランク・スコア内訳も示す。「今回の記録」は薄い区切り線と控えめなテキストの読み取り領域で、展開操作は設けない。正解が 0 問なら領域を省略する。

`components/molecules/ProblemReviewCard.tsx` は一覧への入口を小さくまとめ、リザルトのカードには広告条件を表示しない。問題一覧の解けなかった問題には未解放なら動画視聴のバッジ、有効なリワード期間中なら「見放題中」を表示し、読み上げにも含める。購入リンクは控えめな 1 行にする。リザルトのカードには動画視聴ボタンを置かず、解けなかった問題を開く時の確認から動画視聴へ進む。問題一覧にも控えめな広告削除の購入リンクを置く。一覧が次のプレイで切り替わる注意は問題一覧内に表示する。当初の判断は [ADR-0015](./decisions/0015-review-first-result-screen.md)、主操作の整理は [ADR-0016](./decisions/0016-result-action-hierarchy.md)、余白の再調整は [ADR-0017](./decisions/0017-contiguous-result-layout.md)、記録の常時表示は [ADR-0018](./decisions/0018-static-result-records.md)、最終的な上下の配置は [ADR-0019](./decisions/0019-result-summary-and-actions.md)。

## 購入画面

`screens/PurchaseScreen.tsx` は共通モーダルとして、「広告を削除」という見出しと控えめなアイコン付きカードで「広告なし」「未正解の復習も」の 2 特典を提示し、未正解の復習も動画なし・時間制限なしになることを伝える。小幅画面や文字拡大時はカードを縦に並べる。入口による宣伝見出しの切り替えは行わない。特典部分はスクロールでき、購入総額・買い切り/月額料金なし/自動更新なしの説明と購入操作はフッターに置く。エラー通知・承認待ちもフッターに表示する。上部の閉じる/復元と「今は無料で続ける」で、購入せずに呼び出し元へ戻れる。

無料版との比較・購入履歴と復元の説明・問い合わせは「特典・復元について」の開閉できる詳細にまとめ、正解した問題の復習は無料であることを明記する。購入履歴は Apple が管理すること、再インストール・機種変更後も同じアカウントで復元できることを説明する。解答例の対象が今回プレイした全問題であり、次のプレイで一覧が切り替わる条件は、詳細を閉じていても表示する。簡略化の判断は [ADR-0010](./decisions/0010-visual-purchase-benefits.md)、宣伝的な表現を控える調整は [ADR-0011](./decisions/0011-neutral-purchase-presentation.md)。

商品情報の読み込み中・取得失敗・販売不可・購入/復元中・承認待ち・購入済みを区別する。購入済みでは再購入を促さず、特典が有効なことと元の画面へ戻る操作を示す。購入・復元で権利が有効になった後は、それ以前のエラー通知を表示しない。設定の `components/molecules/PurchaseCard.tsx` は詳細画面への入口であり、価格や購入操作を重複実装しない。判断の記録は [ADR-0009](./decisions/0009-shared-purchase-screen.md)。

## 購入権利と失敗時の扱い

`ios/ModernJamaica/PurchaseModule.swift` は StoreKit 2 の検証済みトランザクションと current entitlements を使用し、取り消された購入を除外する。購入フラグを AsyncStorage に保存して権利の証明にしない。`services/purchaseService.ts` が起動・フォアグラウンド復帰・権利更新を反映する。復元はユーザー操作で StoreKit の同期を行う。

キャンセル・承認待ちは購入成功と区別する。商品取得は同時要求を共有し、タイムアウト後はエラー表示と再取得ができる（期限は `config/monetization.ts`）。商品取得失敗時は固定価格を代わりに表示せず、再取得と復元の導線を残す。動画は SDK の報酬イベントを受けた時だけ解放し、早期終了やロード失敗では権利を付与しない。購入・広告の失敗で通常のプレイを止めない。

解答例の期限は端末の時計で判定するローカルな仕組みであり、サーバー検証や複数端末への期限同期は実装していない。問題一覧もメモリ上のみ。購入は iOS 対応で、Android の購入ブリッジはない。

## リリース前の運用設定

以下は必要な設定・確認であり、この文書の存在は完了の証明ではない。

1. App Store Connect に **非消耗型**の商品を登録済み。商品 ID は `PurchaseModule.swift` と一致し、日本ストアの通常価格は **税込500円**。表示名・説明・販売地域・審査画像とメモを設定し、商品を審査用ドラフトへ追加済み。必要な契約・税務・銀行情報と商品の販売状態を提出前に確認する。
2. iOS 用リワード広告ユニットは AdMob で作成済みで、`config/monetization.ts` に本番 ID を設定済み。Release ビルドはこの ID を使う。開発時は `services/adService.ts` のテスト ID を使い、本番広告の自己クリックで検証しない。
3. Xcode/StoreKit テスト環境で購入・保留・取消を確認し、Sandbox/TestFlight と実機でストア商品取得・復元・広告を確認する。テスト広告の結果と本番の fill rate/収益は区別する。
4. アプリ内のプライバシーポリシーと提出用メタデータの URL は Firebase Hosting の [公開先](https://modern-jamaica.web.app/) に統一済み（`config/links.ts` / `fastlane/metadata/ja/privacy_url.txt`）。ルートの `docs/index.html` は Firebase Hosting と GitHub Pages に公開済み。App Store Connect のポリシー URL 変更は次のアプリバージョンで反映される。プライバシー申告・掲載文言・スクリーンショットを提供内容と照合する。料金はストアで設定し、アプリに金額を固定しない。
5. 下表を実施し、端末・OS・ビルド・テストアカウント種別・結果・未確認項目をリリース記録に残す。

## 計測と収益判断

`services/analyticsService.ts` の既存イベント送信経路を使用する。新規の主なイベントは `result_action`（retry/menu）、`review_offer_viewed`、`review_reward_requested`、`review_reward_earned`、`review_opened`（purchase/reward/locked。問題一覧を開いた時点）、`remove_ads_purchase_started`、`remove_ads_purchase_result`、`remove_ads_restored`、`ad_shown`、`ad_revenue`。購入画面には `purchase_offer_viewed`（source/layout、現在の layout は `visual_benefits_v2`）と `purchase_offer_closed`（source/owned）を追加し、購入開始・結果・復元にも `source`（menu/settings/result_review）を添える。購入の結果は purchased/cancelled/pending/error を区別する。購入数や売上の確定値はストアのレポートと照合する。広告の推定収益も AdMob レポートと照合し、通貨・precision・SDK が送る値の単位を実機で確認してから集計する。

**収益維持は未検証の仮説**。バナーは少量の AdMob 実績で収益寄与が小さかったため廃止し、インタースティシャルは自然な区切りに限定して継続する。UX 改善や購入増の因果的効果は未検証であり、収益が維持される保証ではない。

以下は運用案で、実測結果や自動ロールバック機能ではない。

- 変更前後それぞれ同じ曜日を含む期間を取り、可能なら 14 日以上、地域・OS・新規/既存ユーザー・集客条件を揃えて比較する。配信量が少なければ延長し、少数の購入だけで成功判定しない。
- 主要指標は総収益/DAU（広告＋手数料・返金を考慮した買い切り収益）。広告形式別収益、表示/DAU、fill rate、購入転換率を併記する。買い切り初期売上の一時的な増加も分離する。
- UX は `result_action` の retry 比率、ユーザーあたりゲーム数、D1/D7 継続率、復習利用率、広告・購入失敗を比較する。起動回数等の分母を揃え、前後比較の季節性や集客差を明記する。
- **見直しの暫定基準案**: 比較可能な 2 週間で総収益/DAU が 15% 以上低下し、D7 継続率や再プレイに改善が見られない場合、次回配信の展開を止めて原因を調べる。母数不足なら閾値だけで断定しない。購入権利喪失・二重広告・進行不能は収益を待たず修正対象。
- ロールバックは次のアプリ更新で未購入者向けの閾値や配置を調整する。リモート設定は未実装。購入済み特典と獲得済みの期限は維持し、「もう一度」に広告を戻す前に任意広告の供給と購入導線を確認する。
